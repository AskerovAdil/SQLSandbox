# SQL Sandbox

Песочница для тренировки SQL перед собеседованиями. Работает целиком в браузере: PostgreSQL в WASM ([PGlite](https://pglite.dev)), без сервера.

**Открыть:** https://askerovadil.github.io/SQLSandbox/

Данные хранятся только в этом браузере на этом устройстве.

## Быстрый старт (локально)

Нужен только Node.js LTS версии 22: https://nodejs.org/

1. Скачайте или клонируйте репозиторий.
2. Windows: дважды щёлкните `start.bat`. macOS/Linux: `./start.sh`.
3. Браузер откроется сам, на `http://localhost:5173`.

Скрипт сам проверит Node, установит зависимости при первом запуске и запустит приложение.

Ручной вариант: `npm install`, затем `npm run dev`.

## Вкладки и схема

- Каждая вкладка — отдельная база данных. Таблицы одной вкладки не видны в другой.
- Двойной клик по имени вкладки — переименовать. Перетаскивание меняет порядок.
- Кнопка с копией дублирует вкладку вместе с данными. Кнопка сброса удаляет все объекты базы, код остаётся.
- Слева — схема текущей базы: таблицы, представления, временные таблицы, колонки с типами, ключи и индексы. Обновляется после каждого выполнения. Клик по таблице вставляет `SELECT * FROM … LIMIT 100` в редактор.
- Переключатель справа от вкладок выбирает тему: «Системная», «Светлая» или «Тёмная». Выбор сохраняется.
- Автодополнение в редакторе: ключевые слова, таблицы и колонки текущей базы. После `alias.` или `таблица.` предлагаются только колонки этой таблицы; алиасы берутся из FROM и JOIN.

## Таблицы сессии

Правая панель показывает состояние базы после каждого выполнения.

- **Данные**: карточка на каждую таблицу, колонки с типами, PK/FK/NOT NULL, первые 50 строк с кнопкой «показать ещё». Подсветка относится к последнему выполнению: новые строки зелёные, изменённые ячейки жёлтые, удалённые строки зачёркнуты. Новая таблица помечена `new`, удалённая плавно уходит. Фильтр по имени и сворачивание карточек. Граница панели перетаскивается.
- **Диаграмма**: ER-схема. Связи идут от колонки внешнего ключа к колонке, на которую он ссылается. Раскладка автоматическая, перетащенные вручную узлы запоминаются для каждой вкладки. Кнопки «Уместить» и «PNG».
- Если скрипт упал на середине, панель показывает состояние на момент ошибки и плашку с номером statement.
- Снимок строк ограничен 5000 на таблицу. Без первичного ключа строки сопоставляются по ctid: UPDATE может выглядеть как удаление и вставка.

## Публикация на GitHub Pages

1. Откройте репозиторий: **Settings → Pages**.
2. В разделе **Build and deployment → Source** выберите **GitHub Actions**.
3. Сделайте push в `main`. Workflow `.github/workflows/deploy.yml` выполнит `npm ci`, `npm run check`, `npm run build` и опубликует `dist`. Если проверки не прошли, деплоя не будет.
4. Ссылка появится в **Settings → Pages** и в выводе job `deploy`. Адрес имеет вид `https://<user>.github.io/<repo>/`.

Base-путь берётся из имени репозитория в CI автоматически. Для ручной сборки под другой путь задайте переменную `VITE_BASE`, например `VITE_BASE=/my-path/ npm run build`.

## Почему `dist/index.html` нельзя открыть двойным кликом

Приложение загружает WASM-файлы PostgreSQL и скрипты воркеров через относительные HTTP-пути. Браузеры не разрешают такие загрузки для страниц, открытых по `file://`, поэтому `dist/index.html` открывается пустой страницей или с ошибкой. Для проверки production-сборки используйте `npm run preview` или любой статический сервер.

## Если не запускается

- **Не та версия Node.** Нужна Node.js 22 LTS. Проверка: `node -v`. `start.bat` и `start.sh` показывают сообщение, если версия другая.
- **Занят порт 5173.** Vite сам выберет следующий свободный порт и покажет его в терминале. Если нужен конкретный порт, запустите `npm run dev -- --port 5180`.
- **Очистка данных IndexedDB.** Если база не открывается, приложение покажет экран с кнопкой «Сбросить сохранённые данные». Вручную: DevTools → Application → IndexedDB → удалите базы с префиксом `/pglite`.
- **Белый экран на GitHub Pages.** Чаще всего неверный base. Проверьте, что репозиторий называется так же, как в адресе, и что сборка идёт в CI, а не вручную без `VITE_BASE`.

## Шаблоны

Меню «+» над вкладками создаёт пустую вкладку или вкладку из шаблона. Сейчас есть два шаблона:

- **Сотрудники**: отделы, сотрудники с `manager_id` для self-join, зарплаты. Примеры: оконные функции, GROUP BY, рекурсивный CTE.
- **Интернет-магазин**: клиенты, товары, заказы, позиции заказов. Примеры: JOIN-ы, агрегаты, подзапросы.

Файлы шаблонов лежат в `src/templates/*.sql`. Часть до строки `-- @@queries` выполняется в базе новой вкладки, часть после неё попадает в редактор. Чтобы добавить шаблон, создайте новый `.sql` в этой папке и добавьте его в `TEMPLATES` в `src/templates/index.ts`.

## История и EXPLAIN

- Вкладка «История» в левой панели хранит последние 200 запусков. Клик вставляет запрос в редактор.
- **Explain** выполняет EXPLAIN ANALYZE для statement под курсором. Запрос идёт внутри транзакции, которая откатывается, поэтому данные DML не меняются. Дерево плана показывает стоимость, фактическое время и число строк. Самые дорогие узлы по собственному времени подсвечены.

## Экспорт и импорт

- **Экспорт вкладки в `.sql`** (иконка файла в тулбаре): DDL, данные и код редактора в одном файле. Значения по умолчанию и последовательности не экспортируются.
- **Экспорт всех вкладок в `.json`** (иконка коробки): код и база каждой вкладки. Файл переносится между браузерами и между локальной версией и GitHub Pages.
- **Импорт** (меню «+» → «Импорт из файла»): `.sql` открывается как новая вкладка. Часть до маркера `-- @@editor` выполняется в базе, часть попадает в редактор. Файл без маркера целиком попадает в редактор и не выполняется. `.json` создаёт вкладки со всеми данными из файла.
